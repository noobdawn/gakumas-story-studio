# 从剧本生成 GSS 工程

目标是交付用户能用当前创作器打开、继续编辑的演出工程。以下导演规则来自用户反馈；参数示例与实现经验分开记录，后续用户指示优先。

## 接手与版本

- 先读当前工作区 `AGENTS.md`、`docs/README.md` 和与任务有关的模块文档，再完整阅读剧本。查找角色—声源表、角色出入、括号心理活动、回忆起止、共同台词和插入素材说明；已有配置能回答的问题不要重复询问。
- 区分“在场角色”“当前出镜角色”“当前说话者”。为场次、台词、剧情单元分配稳定标识；合说的“三人”解析为实际成员，不创建名叫“三人”的角色。
- **制作人发言时，字幕的说话者统一显示为 `P`。** 原稿署名为 `Producer`、`制作人` 或 `学P`（含 `学 P`）时，把这句对白的 `speaker` 写成半角大写 `P`。有译文时，`translation.sourceSpeaker` 也随之写为 `P`。台词正文里的称呼照录，例如「制作人，早上好」。
- 按用户指定目录交付。迭代前检查当前文件及修改时间／哈希，从用户最新版本另存下一版，保护用户修改和媒体。只改变本轮反馈涉及的内容，字幕、译文、音频、口型、滤镜和剧情排时应明确说明哪些保留、哪些改变。
- 不把“总结经验为 skill”理解为重做工程、重新配音、更新 build 或导出视频的指令。

## 配音与翻译

- 优先使用文档和当前创作器已配置的声源映射。只有映射缺失、冲突或声库实际不可用时才询问；可继续完成不依赖该答案的编排。
- **首次把这份私人剧本送往内置 DeepSeek 前，明确询问是否允许。** 说明服务、用途及将发送的台词／上下文范围；“使用日语配音”不等于授权外发剧本。同一任务已授权的相同范围无需重复询问，新增剧本或超出原范围另行确认。不要输出密钥或把私人全文打包进 skill。
- 保留中文原文与日语译文的对应关系。先保存译文，再做称呼、人名、专有词与发音替换检查，随后使用已配置声库合成。复用已验证且未修改的译文和配音。
- **用于日语配音的英文要转成假名。** 从全剧找出英文单词、选手 ID、组合名、缩写和字母数字混写。先查当前创作器的发音替换表，命中时采用已配置的读法，例如 `SyngUp! → シングアップ`。未收录的作品专名查原作口播或官方注音，选手名查日语实况中的称呼，缩写按语境选择逐字母读法或惯用读法。日语配音译文写出读法，中文原稿和中文字幕保留原拼写。前后呼应、回忆重播及中文音译指向同一人时统一读音。
- Cook 前核查译文和应用本机发音替换后的实际朗读文本，查出残留的半角、全角拉丁字母并逐项处理。用户要求重新翻译并 Cook 全剧时，逐句重译、对所有有声对白实际触发 Cook，以新音频时长和音素重排剧情、更新口型。纯停顿保留静默。抽查含专名的成句，核对名字没有被拆成字母、吞音或重复朗读。
- 语音时长确定后重排剧情，再绑定镜头、出镜、效果和动作；不要靠硬编码绝对秒数维持同步。普通对白的口型与表情嘴部通道协调；心理独白通常不张嘴，除非剧本另有表演要求。

## 用户的镜头规则

### 原稿标记与换场

- 先把场景标题、段内换景、时间牌、停顿、音效、叠加表情及后补素材定位到前后两句对白。将演出指令放到对应轨道；保留角色实际说出的正文和括号里的心理活动。与旧版有出入的台词、字幕、译文、声音和口型一起更新。
- **跨时间或场合要有转场动画**，包括同一地点换到另一天、另一场谈话，以及进出回忆。连续对话里的正反打、人物出入按镜头调度。原稿明确“不要用转场”时，在该处硬切。片头直接开场即可。
- 按叙事意思选择转场。时间跳跃可用时钟，换地点或会面可用条带。把场景、人物和滤镜的切点放在实际全遮挡区内；日期牌在转场揭开后出现。将转场、音效和标记绑定到剧情段落，给指定停顿和插入视频／截图留足可用时长。
- **代码 UI 沿用《学园偶像大师》的界面风格。** 以角色为画面主体，使用半透明底、清楚的字级和局部强调色。日期牌遵循原稿指定的位置和文字。查阅[游戏 UI 截图与演出做法](references/game-ui.md)，其中提供原图出处、横屏适配和抽帧方法。
- **左上信息弹窗按用户的「亲密度／第1话」参考图制作。** 采用半透明灰底、白字、平直左边和圆弧右端。左端固定，从左向右伸出，完整停留数秒，再从右向左收回。展开时裁切内容，保持字形和字号稳定；默认可从半秒伸出、三秒定格、半秒收回开始试排。
- 日常音效优先在当前受管理批次按实际动作查找，区分开门、关门、开锁、敲门、来电铃声与震动。缺少时可选有明确使用条件的实录或自制拟音，记录作者、来源及处理方式。可复用的声音以中文可检索名称注册到 GSS 的“通用素材”音效分类，在工程里引用同一素材。只在角色实际执行或听到动作的时刻落声音；一句台词提到电话不必自动加来电声。

### 对话构图

正常对话保持**腰部以上**的景别，下沿在腰线附近或更高，不露出大腿。角色与制作人图片切换时，在实际画面中核对头部大小、头顶留白和身体占画面比例，使两边的构图接近。

机位按当时参与对话的总人数分配，学 P 参与时也计入人数。切到单人镜头时仍按这个人数安排。

| 同场组合 | 默认机位 |
| --- | --- |
| 仅 2 人（学 P＋1 人，或两名其他角色） | 两人都用正面机位，身体正对镜头，无需额外偏转 |
| 学 P＋2 人（共 3 人） | 第一人左侧 45°，第二人右侧 45° |
| 学 P＋3 人（共 4 人） | 第一人左侧 45°，第二人正面，第三人右侧 45° |

- 在分镜记录中写明第一、第二、第三人的顺序，轮流发言时沿用，用户可调整。镜头左右按实际画面方向核对。角色进出时更新在场集合。表外组合按实际人物关系设计。
- 共同说话或共同反应时让实际成员同框。普通发言可以切单人镜头，分镜仍依据在场关系。
- 按角色实际头高、腰线、姿势、动作幅度与字幕遮挡区校准机位，检查动作中和回到常驻后的构图。多人同框也应保留腰部以上景别，必要时收拢站位，不能只拉远相机露出下半身。制作人若为 2D 立绘，以当前图片的实际屏幕构图作对照，不假设它具有 3D 侧面或透视。

情绪激烈时，结合面部表情选择合适试镜，不必每句都加特写：

- 头部特写：较大 FOV，并推进相机，形成大头效果；仅增大 FOV 会让主体变小。
- 眼部特写：从左眼平移到右眼，产生盯视感；以角色当时眼位和头部运动校准，记录左右定义。
- 上半身侧面略仰视：用于肢体动作幅度较大的情况。
- 允许依据情绪尝试其他镜头，说明试验目的与待反馈点；表情不能无意覆盖已有语音嘴形。

抒情段落可使用场景空镜缓慢平移、2D 背景放大后平移，或向特定物体推进。确认背景是否随相机固定：若固定，移动相机不会产生背景平移，需要使用背景／画面图层的缩放与位移能力。空镜不自动删掉台词或配音。

## 动作与表情

### 按台词编排

- **逐句读角色想做什么、态度在哪里改变。** 普通交谈也要演出倾听、斟酌、追问、掩饰或下决心等具体意图。同一人连续发言时继续分析后面的句子。一句话中途改口、突然领悟或听见关键信息，就把反应落在那个词或那一拍停顿上。用最终配音确定时间，日语语序变化时跟着实际说到的位置走。
- **优先使用角色自己的动作。** 编排常驻姿势、对白手势和情绪反应时，先从当前受管理批次里挑选符合台词意图和镜头的角色专属动作。找不到对应的专属动作，或现有专属动作都不适合这段表演时，再选合适的通用动作。
- 为出镜角色分别安排身体和脸。角色语气平静，也可以在提到物件时伸手示意，说到自己时收回手。心虚时可以强撑笑容、先移开视线。意图延续时沿用合适的姿态，意图改变时从当前表演自然接上新的动作或表情。按当时的镜头选能看清的头、肩、手或眉眼变化，把它落实到对应片段或关键帧。剧本明示的微笑、脸红等落在指定位置。
- 例如手毬连说「我再想想」「等等，时间对不上」「……我去确认」。第一句低头思索、眉心微收。第二句在「等等」抬眼，到「对不上」才蹙眉，手势可以延续。第三句在停顿里收回手，说出决定时抬头看向对方，目光定住。按当前角色可用的素材实现这些变化。

### 表情选择与脸部贴花

- 逐处找出原稿里的表情提示，明确哪个角色在哪一句、哪个词或哪一拍停顿作出反应。「盯视」「无语」「冷笑」从该角色可用的完整表情中，按台词挑选合适的视线、眉眼和嘴角。只需调整一处时可选单项形变。片段名可以手动填写，判断画面效果要看它引用的素材在该帧驱动了哪些通道。
- **「黑脸」要看见额头和眼周的阴影，「黑脸微笑」还要看得出笑意。** 先选符合角色态度的基础表情。镜头里已有合适的笑容就保留，完整表情已带出阴影就沿用它的曲线。缺阴影时，在同一角色的「表情叠加」轨添加「脸部阴影」。在停顿帧看嘴角和眉眼，角色开口时再核对笑意与对白口型能否同时读出。
- 「三人黑脸」要给镜头中作出反应的三名角色分别安排阴影，包括听者。把贴花起止绑定到相应剧情单元。反应跨句时持续到收势，淡入淡出随表演节奏调整。交付前按原稿逐处核对，在指定帧看每张脸，再看反应结束后是否按时收起。其他贴花的选材和漏显查法见[脸部贴花与同帧验证](references/gss-engineering.md#脸部贴花与同帧验证)。

### 常驻姿势与动作衔接

- 常驻基础使用**姿势**，例如【月村手毬 待机 001 姿势 身体】，再叠加律动起伏。不要用一个名称像“待机”的普通循环动作冒充静态姿势。
- 检查当前资源的 `isPose`、`isAdditive` 与可用性。优先个人姿势和原生增量律动；未找到时明确告诉用户查到的缺口。若先用通用姿势试排，标明临时替代，不称为该角色个人姿势。
- 按手势本身安排进入、保持和收势。可跨句保持同一个意图，也可在一句话中途收势或换姿。字幕换行时保持衔接。优先使用相容的原始资源，缺保持素材可取样核对后延续进入动画的末态，缺退出素材可平滑混合回常驻并注明过渡近似。
- **保持姿态不等于冻结整个角色。** 进入动画播完、保持末态或静态姿势时，仍须叠加相容的原生增量律动，维持呼吸和身体起伏。不能因为基础片段仍在时间轴上，就把整段保持期间的律动停掉。当前实现可用 `condition: always` 的 additive 常驻层覆盖进入—保持—返回，核对幅度、骨盆和手势后调整权重；如需在进入／退出动作中减弱律动，应另作连续权重过渡，保持区间不能归零。
- 独立反应完成后，按下一拍的台词接下一个动作或回常驻。`condition: resident` 仅在无基础动作时生效。
- 发现下沉、跳位或只在动作中正常时，阅读 [工程验证与故障排查](references/gss-engineering.md)。外层 root 不变，不代表骨盆和头部世界位置不变；不要先用整体抬高角色补偿。

## 回忆与心理活动

- **回忆：黑白画面＋对应声音效果。** 用户明确了黑白和声音应有回忆感，没有指定固定音频算法。轻回声是本轮试用方案，应保留可调参数并试听，不写成必须的唯一方案。
- **心理活动默认用思考动作和思索表情。** 角色盘算、回想或自问时，选适合本人的思考姿势，如略低头沉思，配合收眉、垂眼或视线停留。内心独白通常闭口，眉眼和身体仍随念头变化。只有 2D 立绘时，按同样的转折选用已有的思考或情绪差分。
- 念头转为强烈的惊慌、愤怒或坚定时，在触发它的词或停顿处换成相应动作和表情。例如角色想到后果才慌，就让前半句保有沉思，到意识到后果时突然抬头、睁大眼。若一开始就在惊慌中，直接从惊慌演起。
- 心理活动沿用暗角，中央保持可读。回忆中的独白可同时叠加回忆效果。
- 先确认当前 build 是否已有对应效果；已有则复用。缺少时说明能力缺口，在本次任务确实授权实现的范围内补齐，不能只写入一个 Player 不认识的效果名称。
- 效果跟随剧情起止；画面滤镜通常放在字幕下方，覆盖背景、角色及制作人立绘。声音效果放到相应声音片段，并保留原始配音文件。

## 验证与交付

- 修改工程 schema、剧情绑定或动作层前，按需读 [工程验证与故障排查](references/gss-engineering.md) 并核对当前实现。不要把旧研究生成器的资源 ID 或绝对时间直接复制到新工程。
- 检查工程解析／保存往返、素材解析、剧情重排后镜头与效果绑定、配音与口型对应。普通静态构图、多人同框、动作切换边界及反馈时间点分别抽查。
- 选剧中有代表性的连续发言和心理独白，在触发词前后对照画面与配音，确认能看出角色从什么态度变到了什么态度。若台词已转折而画面仍只有待机、呼吸和口型，在漏掉的词句上补动作或表情。检查原稿指定的表情是否清晰、普通对白的口型是否正常，以及心理独白是否误跟旁白动嘴。
- 连续播放并跳回检查动作衔接，确认相邻句不重复起手、保持时不突然放手。保持区间至少取两个不同律动相位，确认身体仍有起伏。对照制作人图片，抽查各角色和多人画面的头顶、腰线及动作极值。分别记录实际试听、可见预览及完整导出的验证范围。
- 遵守当前工作区的预览与进程规则。记录可见界面由谁验收，完成验证后关闭本轮启动的进程并检查退出与占用状态。
- 交付新工程路径、关键改动、建议检查的时间点、替代素材和待确认观感。把用户下一轮反馈关联到角色、剧情单元、时间点、实际表现和期望表现。
